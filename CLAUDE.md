## Architecture

This is a **PWA** (Vite + React 19 + TypeScript) for managing dance studio clients, groups, and subscriptions. It follows a Feature-Sliced Design (FSD) layer structure:

```
src/
  app/          # App entry, router (wouter), Zustand store
  pages/        # Route-level components; also hosts the API client (src/pages/api/)
  widgets/      # app-shell (layout/nav wrapper)
  features/     # Upsert dialogs for clients, groups, subscriptions
  entities/     # Reusable domain UI (tables, badges) + thin type re-exports
  shared/       # api re-export, hooks, lib utilities, shadcn/ui components
```

**Path alias:** `@/` maps to `src/`.

### API layer (`src/pages/api/`)

The REST client is built with `openapi-fetch` against types generated by `openapi-typescript` from the backend OpenAPI spec (`src/api.types.ts`). Domain types (`Client`, `Group`, `Subscription`, etc.) are derived directly from the generated paths — not hand-written. All API calls live in `src/pages/api/index.ts` and are re-exported through `src/shared/api/index.ts`. The base URL comes from `VITE_API_BASE_URL`.

### Offline / sync

`src/shared/lib/db.ts` defines a Dexie (IndexedDB) schema with tables for clients, groups, abonements, sessions, attendance, teachers, tags, and an **outbox** (for queuing mutations when offline). The outbox pattern is in place but sync logic is not yet fully implemented. `useOnlineStatus` tracks `navigator.onLine` and writes to the Zustand store (`useAppStore`).

### State management

Zustand (`useAppStore`) holds only cross-cutting global state: `isOnline` and `syncStatus`. All other state is local `useState` inside page components — pages fetch their own data on mount.

### Page pattern

Each page (`ClientsPage`, `GroupsPage`, `SubsPage`, etc.) manages local state for the list, a dialog open flag, and the item being edited. Mutations call the API and update local state directly (no global cache). Errors surface via `sonner` toasts.

### Subscription period calculation

`src/shared/lib/calcPeriodEnd.ts` computes the end date of a subscription period by walking forward from the start date, counting class days (per group weekdays) that are not holidays. It factors in makeup sessions for illness absences.

### UI

Components come from shadcn/ui (Radix UI primitives + Tailwind). Raw component files are in `src/shared/ui/`. Tailwind config is in `tailwind.config.js`; `@/` aliases are wired in `tsconfig.json` and `vite.config.ts`.

### ESLint rules worth knowing

- `@typescript-eslint/consistent-type-imports` — use `import type` for type-only imports
- `simple-import-sort` — imports are auto-sorted; run `lint:fix` after reordering
- `react/react-in-jsx-scope` is off (React 17+ JSX transform)
